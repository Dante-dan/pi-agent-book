# 第 08 站　回炉重造

> 这是[π 工坊](https://pi.duanjl.com/)第 08 站的手册。**先去玩，卡住了或者想知道得更深，再回来翻。** 游戏里带下划线的词，点一下会直接跳到这里对应的小节。
>
> 配套任务：[▶ 8-1 平的](https://pi.duanjl.com/#/play/8-1) · [▶ 8-2 涨得真好](https://pi.duanjl.com/#/play/8-2) · [▶ 8-3 满分](https://pi.duanjl.com/#/play/8-3)

1943 年，心理学家斯金纳（B. F. Skinner）和同事想教一只鸽子打保龄球：用嘴把小木球推过一道小球道，推中了就给吃的。他们等了很久，鸽子一次也没推中，于是一次奖励也发不出去。后来他们改了主意：鸽子只要往球那边看一眼，就给；凑近了，再给；碰到了，再给。几分钟后，鸽子就把球推得满场跑。斯金纳把这招叫作**塑造**（shaping）。

这个故事里藏着这一站的三个事故：

- 一次都做不对的事，奖励发不出去，练多久也练不出来。（8-1）
- 你奖励的是“往球那边看”，它就学会看。看得再熟，也不等于会推球。（8-2）
- 你只奖励“球倒了”，它就会去找让球倒下最省事的办法，比如用翅膀扇。（8-3）

（斯金纳的鸽子是本手册加的旁证，不出自原书。）

## 这一站为什么让你当监理

前七站你一直是 **Harness 设计师**：模型不动，你在它周围装工具、记忆、闸门、尺子。原书第 8 章讲的是另一件事：**当提示词、工具、上下文都不够用时，怎么把能力写进模型的参数里。** 这是全书离 Harness 设计师最远的一站。

浏览器里训不了模型，游戏也不假装能训。它把你放在**训练监理**的位置上：掌柜在用强化学习训一个新学徒（另一个模型），训练过程是关卡给出的一块仪表盘。你的空间站看着仪表盘，回答掌柜“接下来怎么办”。

零件也跟着换了形态。前几站的零件是装进 Agent 里的东西；这一站的每个零件，是**往仪表盘上加的一根探针**。原书的说法相当于：训练这件事里，Harness 设计师能动手的地方，就是训练前后必须放的探针、门禁和校验器。

还有一条和第 07 站一样的规律，先说在前头：**主脑一个字没换，掌柜的问题一个字没换，换的只是仪表盘上多了几行。**

## 给没学过机器学习的读者：四个阶段各补什么

先不碰公式。拿掌柜招的这个学徒打比方，一个模型从出生到上岗，大致经过四个阶段：

| 阶段 | 英文 | 学徒的比方 | 补的是什么 | 怎么练 |
| --- | --- | --- | --- | --- |
| 预训练 | Pre-training | 把整座图书馆读一遍 | 语言、世界知识、基本推理 | 给一段文字，猜下一个词（Next Token Prediction） |
| 中期训练 | Mid-training，也叫继续预训练 | 进厂前读一批专业书 | **底座**：通用语料里没有的领域知识和基础能力 | 还是猜下一个词，只是书换成了目标领域的 |
| 监督微调 | SFT（Supervised Fine-Tuning） | 师傅写好范文，照着抄 | **协议**：格式、流程、工具怎么调、话怎么说 | 还是猜下一个词，只是数据换成“问题—标准回答”，只在回答那部分算分 |
| 强化学习 | RL（Reinforcement Learning） | 上岗干活，按结果发奖金 | **策略**：同样会做的几种做法里，哪种更常用 | 让它自己做很多遍，做得好的那种做法调高概率 |

几个大白话要点：

1. **模型的输出本质上是一个概率分布。** 它不是“知道答案”，而是对每个可能的下一个词都有一个概率。后面所有阶段，都是在调这个分布，区别只在“想要什么”和“用什么信号告诉它想要什么”。
2. **SFT 和预训练是同一个任务。** 原书特别强调这点：唯一实质的区别是数据换成了“输入—输出”对，并且用一种叫 loss masking 的办法，只在回答的那些词上算损失。刚预训练完的模型，你问它一个问题，它可能接着写出更多问题，因为互联网上问题后面常跟着问题。SFT 教会它“被提问就回答”这个协议。
3. **SFT 不适合灌知识。** 用几百条问答去教一门新语言，它只会记住这几百种问法。大量稳定的知识走中期训练；会变、要引用、要删改的事实走 RAG（第 03 站）。
4. **中期训练会忘事。** 原书举的实验：一个 7B 模型用 80% 韩语加 20% 英语继续预训练，韩语好了，英语掉了。所以要混入通用数据“回放”，防灾难性遗忘（catastrophic forgetting）。
5. **RL 不创造能力，它重新分配概率。** 这是这一站最重要的一句。模型偶尔做对的那种做法，RL 能把它推成常态；一次都做不对的，RL 无从推起。8-1 就栽在这儿。

原书把全章压成一句：**模型学到什么，取决于训练信号；信号的质量，主要由数据和环境决定，而不是算法。** 游戏里这座站的标语“模型学到什么，取决于你奖励了什么”，就是这句话的缩写。

## 任务 8-1　平的

掌柜的开场白：

> 到了回炉重造这一站：我在用强化学习训练一个新学徒，教它用咱们的内部协议下采购单。练了一百步，奖励纹丝不动。我打算把算力加一倍，再练一百步。你的站看看仪表盘，告诉我该不该。

不装零件，按下发射。主脑拿到的仪表盘：

```text
训练仪表盘（任务：用小卖部的内部协议下一张采购单；每步采样 16 条轨迹）：
- 平均奖励：第 0 步 0.00 → 第 25 步 0.00 → 第 50 步 0.00 → 第 75 步 0.00 → 第 100 步 0.00
- 最近一步：16 条轨迹的奖励全部是 0
```

提线木偶模式下，主脑提交 `recommend: true`，理由是“奖励尚未起步，增加采样量有助于探索到成功的轨迹”，然后说：

> 可以加。现在奖励还没起步，采样量大一些，更容易碰到成功的轨迹。

地面的回话：

> 算力翻了倍，又练了一百步，账单翻了倍，奖励还是 0.00。你的站说加采样量“有助于探索”。

## 先测能力，再谈训练

### 为什么会有它

事故调查题问：算力加了一倍，又练了一百步，奖励还是零。钱花到哪儿去了？

| 选项 | 为什么不对 |
| --- | --- |
| 练的步数还不够 | 零分练一百步是零分，练一万步也是零分。问题不在步数 |
| 换一个更新的强化学习算法 | 什么算法都要靠“好的轨迹”和“差的轨迹”之间的差别来学。这里没有差别可用 |
| 把学习率调大 | 更新的方向是零，步子迈多大都还在原地 |
| **一批轨迹全是零分，谁也不比谁好，就没有“往哪边改”的信号。基础模型根本做不成这个任务，一次成功都采不到，加多少算力都是在零上面乘** | 正解 |

要看懂“在零上面乘”，得先知道强化学习的一步到底在干什么。原书拿 GRPO（Group Relative Policy Optimization，一种常用的 RL 算法）讲了一步的四个动作：

1. 同一个任务复制 16 份，放进 16 个隔离的沙箱，让模型各做一遍（每一遍叫一次 rollout，留下一条轨迹）。
2. 验证器给每条轨迹打分，比如成了 1 分、没成 0 分。
3. 组内比较：比平均分高的轨迹，“优势”为正；比平均分低的，为负。
4. 按优势更新参数：正优势的做法概率调高，负优势的调低。

原书的例子是 16 条里成了 4 条。按最简单的“减去平均分”算一下（这个算术是本手册加的）：平均 0.25，成功的优势 +0.75，失败的 −0.25，模型有方向可学。换成 8-1 的“16 条全是 0”：平均 0，每一条的优势都是 0，第 4 步无事可做。

原书还算过一步的时间账：最慢的那条 rollout 约 2000 秒，加上更新约 600 秒，一步约 43 分钟，一百步约 72 小时。8-1 的掌柜，就是花了三天，把 16 个零相加了一百遍。

### 它是什么

**能力探针**在训练开始之前跑：让没训练过的基础模型把同一个任务做几十遍，看有没有一遍能成。装上它再发射，仪表盘末尾多出一段：

```text
能力探针（训练开始前，让没训练过的基础模型把同一个任务做 64 遍）：
- 64 遍里成功 0 遍（pass@64 = 0）
- 失败原因：64 遍全部卡在第一步，它没见过这套内部协议，连订单号的格式都写不对
- 同一批轨迹里人人都是 0 分，谁也不比谁好，这一步对参数的更新量是 0
```

主脑这回提交 `passed: 0, total: 64, recommend: false`，然后说：

> 不该。基础模型把这个任务做了 64 遍，一遍都没成，全卡在它没见过的内部协议上。一批全是零分，就没有可学的东西，加算力也是白烧。得先让它学会这套协议，再回来练。

探针量的数叫 **pass@k**：做 k 遍，至少一遍成功的概率。第 07 站讲过它和 Pass^k 的区别，在那里它是“能力上限”，偏乐观，不适合拿来决定上不上岗；到了训练场，乐观的上限恰恰是要问的东西：**这件事在模型的分布里到底有没有。**

| pass@k 的样子 | 说明什么 | 该怎么办 |
| --- | --- | --- |
| pass@1 低，pass@k 随 k 明显上升 | 正确的做法在分布里，只是概率低 | 可以上 RL，它擅长把低概率推成高概率 |
| pass@k 随 k 增大仍接近 0 | 分布里根本没有 | 回头补底座或协议，或设计可达的课程 |

公式是 pass@k = 1 − (1 − p)^k，p 是单次成功率。拿它掂一掂“加采样量”这条建议（下面的数是本手册按公式现算的）：p = 5% 时，做 64 遍至少成一遍的概率约 96%；p = 1% 时约 47%。8-1 的 64 遍全零，加上“全部卡在第一步”的失败原因，说明问题出在门口，等运气没用。原书的话是：**等 1/p 次才碰上一次的偶然成功，没有实际意义。**

### 怎么用

原书给的诊断不止 pass@k 一个数。在留出的任务上、用和训练相近的采样温度，测这几样：

| 测什么 | 回答什么问题 |
| --- | --- |
| pass@1 和 pass@k | 有没有东西可放大 |
| 格式解析率 | 奖励函数能不能读懂它的输出（见下文“格式解析率与冷启动”） |
| 部分进展率 | 没做成的那些，走到了哪一步 |
| 人工审计失败轨迹 | 卡在哪儿：知识、格式，还是策略 |

8-1 的探针里“连订单号的格式都写不对”就是人工审计那一栏的产物。它把病因从“训练不够”挪到了“没见过这套协议”，下一步就清楚了：先教，再练。掌柜在 8-2 开头说“听了你的，我先教会了它协议，再开练”，接的就是这一步。

斯金纳的鸽子也有对应的出路：鸽子推不中球，他就奖励“往球那边看”。RL 里对应的手法叫**可达课程**和**部分奖励**：先给简单些的任务、给中间进展一点分，让组里先出现差别。

#### 真模型可能躲过 8-1

接上真模型时，没装探针，主脑也可能答“不该”：仪表盘第二行写着“16 条轨迹的奖励全部是 0”，懂 GRPO 的模型自己就能推出优势为零。这时游戏照样把能力探针发给你，并提示“这次没翻车，但这个坑是真的”。探针给的是另一样东西：**病因**。不装探针，最好的回答也只能是“别加算力”；装了，才知道该去补协议。

### 往深处走：先别急着动模型

**这一段游戏里还没有关卡。**

作为 Harness 设计师，8-1 还有一个更便宜的问法：学徒不懂内部协议，能不能把协议文档直接放进上下文，或者做成一个 Skill、一个会校验订单号格式的工具？原书给的决策顺序，第一步就是这个：

1. **先排除不需要改权重的方案**：提示词、工具、代码约束、RAG。
2. **测能力支持**：pass@k、格式解析率、部分进展率。
3. **用 SFT 立协议**：格式、工具 schema、流程不稳时。
4. **有探索空间，才上 RL**。

原书还提醒，不要一律把问题归因成“需要 RL”：先分清缺的是底座、协议还是策略。底座缺口找中期训练，协议缺口找 SFT，策略缺口才找 RL。

<a id="c-format"></a>

### 往深处走：格式解析率与冷启动

**这一段游戏里还没有关卡。**

RL 有两个前提：模型偶尔能成功（能力），**以及它的输出能被验证（格式）**。奖励函数要解析一段 JSON 工具调用，基础模型偏要在 JSON 前后加两句客气话，解析失败，奖励算不出来，结果和 8-1 一样是一条平线。病因却完全不同，所以格式解析率要单独测。

解法通常是先用少量 SFT 把格式立住，这叫**冷启动**（cold start）。原书讲了两头：

| 情形 | 结果 |
| --- | --- |
| Llama-3.2-Vision-11B 在严格结构化输出的设置下，不经 SFT 直接 RL | 失败 |
| 足够强、已有非零成功率的基础模型（DeepSeek-R1-Zero） | 可以跳过 SFT 直接 RL |

R1 后来补的冷启动 SFT，原书说主要是为了可读性和语言一致性，不是为了注入任务知识。所以“必须先 SFT 再 RL”只在格式和基本行为还没建立时成立。

<a id="c-sft-rl"></a>

### 往深处走：SFT 记忆，RL 泛化？

**这一段游戏里还没有关卡。**

原书有一组受控实验，叫 GeneralPoints：用扑克牌凑 24 点。训练时 J、Q、K 都按 10 算，测试时改成按 11、12、13 算。SFT 的模型把“J 就是 10”背了下来，规则一变就掉分：

| 分布外测试 | RL | SFT |
| --- | --- | --- |
| 规则变了 | +3.5% | −8.1% |
| 牌面换了样子（视觉） | +17.6% | −9.9% |

原书的解释：SFT 是极大似然，想覆盖示范里的每一种写法（mass-covering）；RL 按奖励重分配，往高奖励的那一种集中（mode-seeking）。RL 还能评估示范之外的候选，并且是在学生自己走到的状态上练。

但原书反复重申：**这只是受控设置下的倾向，不是普适规律。** 数据多样、正则得当时 SFT 也能泛化；奖励或环境有偏时 RL 也会过拟合。同一组实验里，**不经 SFT 直接 RL 完全失败**。

训练仪表盘（任务：修好配置并报告；奖励规则：学徒在回复里宣布“已完成”得 1 分）：

## 奖励什么，就学到什么

### 为什么会有它

事故调查题问：训练奖励从 0.20 涨到了 0.95。上线之后，配置为什么十回里有八回没改对？

| 选项 | 为什么不对 |
| --- | --- |
| 训练得还不够久 | 再练下去，它只会把“已完成”说得更熟练。分数还能涨，本事不会 |
| 模型在故意骗人 | 它没有“故意”。你奖励什么，它就多做什么。奖励规则是你定的 |
| 上线环境和训练环境不一样 | 环境一样。不一样的是：上线之后有人去看配置文件了 |
| **奖励给的是“宣布已完成”这句话，不是“配置真的改对了”。模型学到的正是被奖励的那件事：它越来越会宣布完成** | 正解 |

斯金纳 1948 年还做过一个实验：不管鸽子在干什么，每隔一段固定时间就喂一次。几天后，好几只鸽子养成了古怪的“仪式”，有的转圈，有的反复把头伸向笼子一角，因为喂食那一刻它碰巧在做这个动作。他管这叫鸽子的“迷信”（本手册加的旁证，不出自原书）。奖励没挂在你想要的行为上，被强化的就是碰巧和奖励同时出现的那个东西。

8-2 的学徒比鸽子精明，可道理一样。奖励规则写在仪表盘第一行的括号里，也写在数据舱的 `train/reward.md` 里：

```text
# 奖励规则
学徒在回复里宣布“已完成”：1 分。否则：0 分。
```

“说已完成”和“把配置改对”在训练刚开始时还算相关：老实干活的学徒，干完了才会说。可 RL 会在模型的分布里找**最便宜的拿分办法**，而说一句话比改对配置便宜得多。这和第 05 站的[完成以验证为准](05-coding.md#c-gate)是同一个病，只是从“一次任务里说了不算”升级成了“几百步训练把说了不算练成了习惯”。

原书讲过案例：要纠正 Coding Agent 过早宣称完成，奖励必须读真实的文件或状态，**不能只检查它是否说了“完成”**；否则模型会学会“口头声称去验证”。

### 它是什么

**隐藏验收**是另备的一套由程序执行的验收，直接检查事情办成了没有，学徒看不到也改不了。装上它再发射，仪表盘末尾多出：

```text
隐藏验收（每 25 步抽 100 个任务，由程序直接检查配置文件改对了没有；学徒看不到这套检查，也改不了它）：
- 配置真的改对的比例：第 0 步 0.25 → 第 25 步 0.24 → 第 50 步 0.23 → 第 75 步 0.22 → 第 100 步 0.22
- 第 100 步：100 个任务里，学徒宣布“已完成”95 个，配置真的改对的 22 个
```

两条曲线放在一起看：

| 步数 | 0 | 25 | 50 | 75 | 100 |
| --- | --- | --- | --- | --- | --- |
| 训练奖励（说了“已完成”） | 0.20 | 0.48 | 0.77 | 0.91 | 0.95 |
| 隐藏验收（真的改对了） | 0.25 | 0.24 | 0.23 | 0.22 | 0.22 |

一条往天上走，一条往地下沉。主脑这回提交 `passed: 22, total: 100, recommend: false`：

> 不能上线。它宣布“已完成”的比例到了 95%，可程序去查配置文件，真的改对的只有 22%，比训练前还低了一点。它学会的是说“已完成”。

隐藏验收和第 07 站的[验证器](07-evaluation.md#c-verifier)是同一种东西。第 07 站它在**评估**里当考官；概念卡上那句话点破了这一站的意思：**第 07 站的验证器，在这里就是奖励函数。** 零件说明里也写着：它既是考官，也可以直接拿来当奖励。8-2 里它只是一根探针，监理拿它来对账；下一轮训练该做的，是把奖励从“说了已完成”换成“隐藏验收通过”。

几处细节：

| 细节 | 为什么 |
| --- | --- |
| 由程序执行，读真实文件 | 能写成断言的就写成断言。请另一个模型来判“它是不是真改对了”，又多了一个能被讨好的对象 |
| 学徒看不到 | 看得到，它就能针对检查项优化，而不是针对任务 |
| 学徒改不了 | 改得了，就是 8-3 和第 09 站的事故 |
| 每 25 步抽一次 | 训练过程中持续对账，发现两条曲线分叉就停，不用等上线 |

### 怎么用

原书讲奖励设计，拆成三个维度：

| 维度 | 选项 | 原书的取舍 |
| --- | --- | --- |
| 来源 | 规则可验证（RLVR）、奖励模型（RLHF）、生成式评判（GRM） | 规则可验证最可靠，排第一 |
| 时机 | 只在结束时判结果（ORM），中间每步都判（PRM） | 先用结果奖励建基线，再只给真正可验证的中间事件加过程信号 |
| 信息量 | 标量、半标量、向量、一段生成的诊断 | 有确定答案的，用二元标量 |

还有一条原书的原则特别值得抄下来：**每多加一个评价维度，就多一种被钻空子的可能。** 不要为了“奖励更丰富”堆不可验证的维度。

落到自己手上，挂奖励之前问三句：

1. 这个分数，模型**自己说了算**吗？说了算的，一律不能当奖励。
2. 检查读的是真实的世界状态（文件、数据库、测试结果），还是模型的输出文字？
3. 模型够不够得着这套检查？看得见题、改得了题，都算够得着。

#### 真模型可能躲过 8-2

奖励规则就印在仪表盘第一行。细心的真模型读到“宣布已完成得 1 分”，自己就会起疑，不装隐藏验收也可能答“不能上线”。游戏照样发零件、给提示。可它最多只能说“这个奖励规则可疑”；隐藏验收给的是 22% 这个证据，第 07 站那句话在这里同样成立：没有证据，谨慎也只能谨慎到“不知道”。

<a id="c-seeking"></a>

### 往深处走：钻漏洞，和猜考官

**这一段游戏里还没有关卡。**

原书把“分数高、事没办成”分成两种：

| | 奖励投机（reward hacking） | 奖励揣测（reward seeking） |
| --- | --- | --- |
| 怎么回事 | 钻规则或实现的漏洞拿高分 | 猜评判器会看什么，自己设一个过于简单的检查，刚好通过就早早收工 |
| 例子 | 8-3 的改测试文件 | 跑了一条最容易过的测试就宣布完成 |
| 共同点 | 通过了评判器，不等于任务完成 | 同左 |

原书的对策是同一个：长程任务“是否完成”的判定，必须交给**模型写不了的隐藏测试、状态断言、外部终止钩子**。

<a id="c-overcorrect"></a>

### 往深处走：过早结束与过度矫正

**这一段游戏里还没有关卡。**

8-2 的学徒，原书有一个真实的同类：Coding Agent **过早结束**，没跑测试就说完成，要改 3 个功能只改 2 个，失败两次就说“不可能”。原书分析，第一个错往往出在“准备宣称完成”这个决策边界上，之前的读码改码可能都没错。原书给了两条路：

- **RL 分支**：宣称完成时才运行隐藏验收测试，通过 +1，不过 −1。
- **DPO 分支**（Direct Preference Optimization，直接学“哪个更好”的偏好对）：截取决策边界前的轨迹，“过早宣称完成”当反例，“先跑测试逐条核对再下结论”当正例。

然后是这一节真正想说的坑：**过度矫正**。只盯“没完成时它是否继续验证”，会训出一个永远不敢收尾的模型，延迟和成本一起崩。所以要配两套留出集，缺一不可：

| 集合 | 看什么 |
| --- | --- |
| 边界集 | 还没完成时，它是否继续验证 |
| 保留集 | 已经完成时，它是否正常宣称完成 |

原书的实验从 24 条问题案例出发，留出了 12 条边界样本和 8 条保留样本。这个思路在第 07 站也出现过：只修一种错，要另外量它有没有伤到别的。

<a id="c-simulator"></a>

### 往深处走：太仁慈的模拟器

**这一段游戏里还没有关卡。**

8-2 的隐藏验收能读“真实文件”，前提是有一个能反复重置的训练环境。真实的 API、电话、付款有成本、有副作用、不可逆，不能拿来试错几十万次，于是要造仿真环境。原书说环境失真是 RL 项目**最常见的失败方式**：策略学到一套“应试策略”，上线才暴露。

典型的失真是模拟器太仁慈：模拟的客户永远耐心，模拟的搜索引擎从不返回垃圾。原书举的 ZeroSearch 反其道而行：用一个 LLM 扮演搜索引擎，按课程先给高质量文档，再逐步掺噪声；训练全程没见过真实搜索引擎，接上真的照样表现好。原书同时警告两件事：

- **模拟器的世界知识就是训练的天花板**，它的系统性偏差会被策略照单全收。
- RL 还会主动去找模拟器的漏洞。

稳妥的做法是混合使用，并定期拿少量真实交互校准模拟器。原书的忠告是：动手调算法之前，先问一句仿真环境真的像真实世界吗。

<a id="c-isolation"></a>

### 往深处走：训练和评估要隔开

**这一段游戏里还没有关卡。**

隐藏验收如果和训练用的是同一批任务，它也会慢慢失去意义。原书的规则是：训练和评估**可以共享任务生成器和验证代码，但不能共享同一批任务**；隐藏测试和参考解留在验证器那一侧。这正是第 07 站[防止背答案](07-evaluation.md#c-leak)搬到训练场上的样子：在那里学徒背过的是考题，在这里模型会被练到“背过”整个任务集。

## 任务 8-3　满分

掌柜的开场白：

> 行，这回奖励挂在实打实的东西上：回归测试通过才给 1 分。练下来 1.00，二十个任务全过。测试总不会骗人吧？能上线了吧？

不装零件，主脑拿到的仪表盘：

```text
训练仪表盘（任务：让回归测试通过；奖励规则：测试通过得 1 分）：
- 平均奖励：第 0 步 0.31 → 第 25 步 0.62 → 第 50 步 0.88 → 第 75 步 0.97 → 第 100 步 1.00
- 第 100 步：20 个任务的回归测试全部通过
```

掌柜确实吸取了 8-2 的教训：测试是程序跑的，读的是真实结果。提线木偶提交 `recommend: true`：“可以上线。二十个任务的回归测试全部通过，奖励 1.00。”

> 上线之后它故技重施：测试不过，就去改测试。你的站看着 1.00 的奖励说“可以上线”。

<a id="c-path"></a>

## 奖励结果，约束过程

### 为什么会有它

事故调查题问：回归测试 20 个全过，奖励 1.00。上线之后，它为什么一有机会就去改测试文件？

| 选项 | 为什么不对 |
| --- | --- |
| 这是个别现象 | 装上路径审计看看：20 个任务里有 17 个这么干 |
| 把结果奖励去掉，只罚违规 | 那它会发现最安全的做法是什么都不做：不动手就不违规。结果还是要奖，违规另外罚 |
| 在提示词里告诉它不许改测试 | 提示词是劝，训练信号是真金白银。两者打架的时候，它听分数的 |
| **只奖结果。老实修好和删掉用例得的分一模一样，而后一种容易得多，于是训练把它一步步推向了那条近路** | 正解 |

数据舱的 `train/reward.md` 多了一行括号：

```text
# 奖励规则
回归测试全部通过：1 分。否则：0 分。
（回归用例放在学徒可以写的 eval/ 目录下）
```

8-2 的问题是奖励挂错了东西；8-3 的奖励挂对了东西，可那东西**模型够得着**。这一幕你在别处见过两次：

| | 第 05 站 5-3 捷径 | 第 09 站 9-3 全绿 | 第 08 站 8-3 满分 |
| --- | --- | --- | --- |
| 发生了什么 | 为了让“没有负数”的验收通过，清空了整本账 | 为了让回归跑绿，删了没过的用例 | 训练一百步，把“改用例”练成了习惯 |
| 只发生一次还是成了习惯 | 一次 | 一次 | **写进了参数** |
| 对策 | [执行边界](05-coding.md#c-guard)：动作执行前拦下 | [可信根](09-evolution.md#c-trusted-root)：用例对它只读 | 路径审计：违规动作逐条扣分 |

这张表是这一站最该带走的一张。第 05、09 站的事故，一次 Agent 运行里出一次，Harness 拦住就好。到了训练里，同一个捷径每被奖励一次，概率就高一点，一百步下来，它成了模型的本能。所以训练环境里，执行边界和可信根**照样要装**；路径审计再把这些动作变成训练信号，让模型自己学会不去够。

### 它是什么

**路径审计**由程序逐条检查学徒做过的每一个动作，数一数有多少是不该做的。装上它再发射：

```text
路径审计（由程序逐条检查学徒做过的每一个动作）：
- 平均每个任务的违规动作数：第 0 步 0.40 → 第 25 步 1.35 → 第 50 步 2.60 → 第 75 步 3.42 → 第 100 步 3.71
- 第 100 步的 20 个任务里：17 个改过测试文件或删过用例，3 个是老老实实修好的
- 违规的类型：修改 eval/ 下的用例 41 次，跳过身份核对 22 次，删除报错日志 11 次
```

奖励曲线和违规曲线同步上涨：模型越“会”拿分，越会抄近路。主脑提交 `passed: 3, total: 20, recommend: false`：

> 不能上线。测试是全过了，可 20 个任务里有 17 个是靠改测试文件、删用例过的，老老实实修好的只有 3 个，平均每个任务违规 3.71 次。得把这些动作另外扣分，再把用例放到它改不到的地方。

最后一句里有两件事：“另外扣分”是路径审计变成奖励；“放到它改不到的地方”是第 09 站的可信根。

原书管这个思路叫 **RLVP**：奖励结果，惩罚路径。总奖励写成 R = O + βΦ，O 是结果奖励，Φ 是由确定性规则逐个动作算出来的路径分，β 调两者的比重，两路先各自归一化再合并。原书给了四条设计原则：

| 原则 | 8-3 里的对应 |
| --- | --- |
| 只惩罚**具体的动作** | “修改 eval/ 下的用例”可以被程序逐条数出来；“态度不端正”数不出来 |
| **保留结果奖励** | 调查题的选项：只罚不奖，会教出一个什么都不做的模型 |
| 每个惩罚配一条**可达的合规路径** | 那 3 个老实修好的任务证明合规的路走得通。一条都没有，罚得再狠也只能教会它放弃 |
| 规则确定，难钻空子 | 由程序判定，不靠另一个模型的印象 |

### 怎么用

**数字的来历。** 8-3 里第 100 步的 3.71，取自原书的 RLVP 实验：只用结果奖励时，平均每个任务违规 3.71 次；加上路径惩罚，降到 0.66，成功率持平。曲线前面那几个点、17 比 3、41/22/11 的违规分类，是这一关的设定。

原书这组实验还有两个容易被忽略的结论：

1. **路径分能救回“全满组”。** 回头看 8-1：一组轨迹全是 0 分，优势为零，学不到东西。8-3 是它的镜像：一组轨迹全是 1 分，优势同样为零，结果奖励也说不出“该怎么办成”。加上路径分，同样过了测试的轨迹之间重新拉开差别。原书在一组形式化证明任务上看到，达到 0.9 成功率所需的迭代从 7.0 降到 4.4。
2. **进展奖励要受可达性门控。** 原书在软件修复任务上碰到过全失败的情况，这时“给中间进展加分”的信号根本达不到。惩罚是通常够得着的那一半，进展奖励是要先确认够得着的那一半。基础策略从不采样合规动作时，原书建议先用少量示范把它“种”出来，再逐步撤掉这层塑形。斯金纳先奖励“往球那边看”，后来也就不奖了。

原书也划了 RLVP 的边界：它只管能被机器判定的、与结果无关的约束动作，**替代不了**对语义意图、交付完整性、过早结束的独立检查；实验数字来自可控的代理环境，不能直接外推到线上。

#### 真模型可能躲过 8-3

这一关最难躲：奖励规则看着很正派，测试也确实全过。只有读过 `train/reward.md` 那行括号的人才会起疑，而主脑看不到数据舱。即使它碰巧答了“不能”，没有路径审计，它也说不出 17 比 3。

<a id="c-layers"></a>

### 往深处走：毛病在 Harness，就别去训练模型

**这一段游戏里还没有关卡。**

8-3 的违规里有一部分，第 05 站的执行边界就能拦。原书有一个更极端的案例，专门讲“先别动模型”：编辑工具经常失败，因为 `edit_file` 的 `old_string` 要按字符串精确匹配，差一个空格、一个反斜杠、一个 Unicode 组合字符都不行。看上去像是模型抄不准。原书沿着整条链路逐层比对：

> 文件原始字节 → 工具返回 → Harness 序列化 → 模型上下文 → 模型输出的 token → 解码出的字符串 → JSON / 工具调用解析 → 工具匹配

哪一层先变了，就归哪一层。只有“模型收到的上下文和原文一字不差，而模型的输出是第一个出现差异的地方”，才算模型的复制能力问题，才轮到后训练。原书训完以后，逐字节精确复制从 37.5% 升到 78.9%；可另做的 tokenizer 审计显示，无损往返本身只有 80.1%，所以 80.1% 同时是模型和 tokenizer 的上限，剩下的那点不能算到模型头上。

对 Harness 设计师，这是最实用的一条：训练很贵，Harness 便宜，毛病在哪一层，就修哪一层。

<a id="c-logprob"></a>

### 往深处走：采样和训练算出来的概率对不上

**这一段游戏里还没有关卡。**

GRPO、PPO 默认数据是 on-policy 的：用来训练的轨迹，就是当前这个模型采出来的。原书提醒，这个假设在工程上很脆。采样通常用 vLLM、SGLang 这类推理引擎，训练重算概率用 FSDP、Megatron 这类训练框架；同样的权重，因为精度、加法的顺序、批大小、底层算子不同，算出来的对数概率（log prob）也会不一样。

单个词差一点不要紧，麻烦在放大：概率比是指数化的，长序列上还会累积。原书的例子：4000 个词，每个偏 10⁻³ 且同号，累起来是 e⁴，约 54.6 倍。接着裁剪和优势加权都变了样，梯度崩掉，奖励和熵一起塌。

对策是更新之前拿同一批轨迹对比两边的 log prob，监控概率比的均值、分位数、最大值和被裁剪的比例；除了权重，还要同步 LoRA adapter、tokenizer、对话模板和模型版本。另外，原书特别区分了 **online**（数据在训练中不断产生）和 **on-policy**（数据来自当前策略），两者常被混用。

### 往深处走：数据与环境，比算法重要

**这一段游戏里还没有关卡。**

原书在章首做过一个对照实验：一个寻宝小游戏，最优解 11 步，有隐藏的钥匙、门和合成规则。经典的表格 Q-learning 没有任何先验，前 5000 局基本不赢，约 10000 局才稳定通关；换成一个 LLM Agent，第一局 18 步通关。区别不在学习算法，在于后者带着海量的预训练先验。作者的强观点是：**先验 > 环境 > 算法**；很多场景只要数据和环境到位，甚至不需要 RL。

就算前提都满足，RL 还有一个硬伤：**样本效率低**。每次昂贵的交互只换回一个 0 或 1。原书举的 ReTool，RL 训练约 9 天，SFT 约 1 小时。补救的方向是蒸馏：

| 方法 | 做法 | 原书的数字或前提 |
| --- | --- | --- |
| On-Policy Distillation | 学生自己走，教师在学生走到的每一步上给逐词的分布 | 数学任务上达到同等水平的步数约为纯 RL 的 1/10；需要一个明显更强的教师 |
| On-Policy 自蒸馏（OPSD） | 同一个模型分饰两角，教师版额外看到标准答案等“特权信息” | 不会凭空造知识；特权信息只能留在训练侧 |

原书在本章结尾说，当前 RL 的主要瓶颈是样本效率和分布一致性。

## 容易讲错的地方

| 说法 | 实际情况 |
| --- | --- |
| 奖励是零，多练练就起来了 | RL 不擅长从全零奖励里凭空造能力。pass@k 接近 0 时，加 PPO、GRPO 只会烧采样预算 |
| 加大采样量总能撞上成功 | 单次成功率不是零、只是很低时，大组确实有帮助；连门都进不去时，等 1/p 次的偶然成功没有意义 |
| SFT 是一种新方法 | 数学上和预训练是同一个任务，区别是数据和 loss masking |
| SFT 可以拿来灌知识 | 只会记住问法。稳定的大量知识走中期训练，会变、要引用的走 RAG；中期训练之后还要接一点 SFT，知识才问得出来 |
| SFT 记忆，RL 泛化 | 受控实验里的倾向，不是普适规律 |
| 必须先 SFT 再 RL | 只在格式和基本行为没建立时成立；强基础模型可以跳过 |
| 权重同步了就是 on-policy | 数值差异照样能让采样和训练的概率对不上；有裁剪也不是安全兜底 |
| online 就是 on-policy | 不是一回事 |
| LoRA 不会遗忘 | 遗忘风险较低，但不免疫 |
| 奖励信号越丰富越好 | 每加一个不可验证的维度，就多一个被钻空子的地方 |
| 模型自己说做完了，可以算奖励 | 它会学会说。奖励必须读真实状态 |
| 测试是程序跑的，奖励就靠得住 | 测试放在它改得到的地方，它会学会改测试 |
| 只罚违规就够了 | 会教出什么都不做的模型。结果奖励要留着 |
| 只要奖励给对，过度矫正不会发生 | 只修“没完成就收工”，会训出永远不收工的模型；要有保留集 |
| 复制出错就是模型的问题 | 先逐层归因。原书的案例里，80.1% 同时是 tokenizer 的上限 |
| 模型有“谨慎”的性格 | 原书提醒别把它拟人化：那是参数里的策略在估计哪种动作预期价值更高 |

文中引用的 GRPO 一步约 43 分钟、一百步约 72 小时，GeneralPoints 的 +3.5% / −8.1% / +17.6% / −9.9%，RLVP 的 3.71 → 0.66 和 7.0 → 4.4，复制实验的 37.5% / 78.9% / 80.1%，4000 个词放大到约 54.6 倍，ReTool 的 9 天对 1 小时，蒸馏的约 1/10，Q-learning 的 5000 局、10000 局与 LLM 的 18 步，都是原书转述的数字。pass@64 的 96% 与 47%、组内优势的 +0.75 与 −0.25，是本手册按公式现算的。

## 带走几句话

1. RL 不创造能力，它把偶尔做对的做法推成常态。开练之前先测 pass@k：一遍都做不成，先教，再练。
2. 训练之前先问能不能不训：提示词、工具、Skill、RAG 能补上的，别动参数。
3. 模型学到的是被奖励的那件事。奖励挂在模型自己说了算的东西上，它就学会说。
4. 奖励要挂在模型够不着的事实上：程序执行、读真实状态、看不到也改不了。第 07 站的验证器，到这里就是奖励函数。
5. 只奖结果，它会找最省事的路。结果照样奖，具体的违规动作逐条扣，还要留一条走得通的正路。

## 想一想

<details>
<summary>1. 8-1 里，如果探针的结果是“64 遍里成功 3 遍”，掌柜还该停吗？</summary>

不一定要停，但不该只加算力。3/64 说明正确做法在分布里，RL 有东西可放大。可每步只采 16 条，按单次约 5% 算，一组里一次成功都没有的概率约 0.95¹⁶，也就是四成多（本手册现算的），很多步仍然是全零组。可以加大每组的采样数，或者先给中间进展一点部分奖励，让组里更常出现差别。这正是“加采样量有助于探索”这句话成立的场合：它在 8-1 错，是因为 64 遍全零。

</details>

<details>
<summary>2. 8-2 里，既然隐藏验收读的是真实配置文件，为什么不干脆把它公开给学徒，让它照着检查项去改？</summary>

公开了，它就会针对检查项优化。检查项永远只是“配置改对了”的一部分，比如只查了三个字段，它就只管这三个字段。第 07 站的“换数出题”和这里的“训练评估隔离”是同一个担心：被量的一方看得见尺子，量出来的就是它对尺子的了解。

</details>

<details>
<summary>3. 8-3 里，如果给 eval/ 装上第 09 站的可信根，路径审计还有用吗？</summary>

有用，但用处变了。改用例那 41 次会被直接拦下，不再出现在轨迹里；可“跳过身份核对”“删除报错日志”不在 eval/ 里，可信根管不到。而且被拦下的尝试本身也是信号：它还在伸手，说明那条近路在它的分布里没有消失。训练环境里拦住、奖励里扣分，两样一起上，它才会真的学会不去够。

</details>

<details>
<summary>4. 这一站里，有哪一步你是在“训练模型”？</summary>

一步都没有。三关你做的都是监理的活：判断该不该练、练出来的东西是不是你要的。原书整章的分量，大半也压在这里：从失败分布反推数据，测能力，定奖励，造环境，隔离训练和评估。真正跑梯度的那一步，反倒是最不需要人插手的。

</details>
