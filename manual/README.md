# 操作手册

这是 [π 工坊](https://pi.duanjl.com/) 的操作手册。游戏里点“手册”弹出来的，就是这里的内容。

## 两层书稿，各管一层

| | 操作手册（这里） | [教材](../book/) |
| --- | --- | --- |
| 用来做什么 | 入门和理解 | 巩固和深入 |
| 什么时候读 | 玩的时候，卡住了或者想知道刚才那一幕是怎么回事 | 一站玩完以后，想把机制和源码弄透 |
| 怎么组织 | 跟着游戏走：一个任务、一次事故、一个零件 | 一站一章：同一个主题，讲到原理、源码和工程取舍 |
| 讲到哪儿 | 讲清游戏里看得见的东西，原书其余内容只点到为止 | 原书这一章的完整因果链，加上 Pi 的实际实现与练习 |

第 N 站的手册和教材第 N 章讲的是同一个主题。推荐的顺序是：**先玩第 N 站，边玩边翻手册，玩完再读教材第 N 章。**

## 写法

- **游戏优先**：手册在游戏之后写，解释的是你刚在屏幕上看到的那一幕。
- **十站加一个专题**：对齐李博杰《[深入理解 AI Agent](https://github.com/bojieli/ai-agent-book)》的十章，另加沙盒专题。
- **每个概念答三问**：为什么会有它、它是什么、怎么用。
- **因果链来自原书**：每一站动笔前先通读原书对应章节，按它的推导顺序排任务，每个零件都由上一步留下的麻烦逼出来。十章的因果链整理在 [`../knowledge/`](../knowledge/)。

## 写作约定

- 文件名 `NN-slug.md`（专题是 `s-slug.md`），工坊服务端按这个规则加载。
- 游戏里引用的概念用显式锚点，例如 `<a id="c-loop"></a>`，放在对应小节标题的上一行。
- 指向任务的链接写完整地址，例如 `https://pi.duanjl.com/#/play/1-1`，这样在 GitHub 上也能点。
