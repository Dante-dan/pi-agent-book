# 第 9 章 Agent 的持续进化

> 出处行号均指 `book/chapter9.md`（全文 425 行，已通读）。

## 一句话主旨
模型部署后不会自己长进，而在线直接改参数又会固化噪声和攻击；所以要在模型外围搭一套“记录证据 → 验证 → 归纳 → 选载体更新 → 独立验证发布 → 整理淘汰”的自主系统（作者称“持续进化”），且验证与安全机制必须在被修改者够不着的地方。

## 起点问题
接前面各章留下的零件：第二章只能让 Agent 在**当前任务内**适应，第三章的记忆沉淀“用户与世界是什么样”，第五章给了改系统的能力，第七章给了评估，第八章给了改参数的方法（§开篇 L3–13）。缺口：零样本能解新任务，却可能处理一万次相似任务后第二天仍犯第一天的错；没有人告诉模型今天哪些做对了、哪些做错了。本章要把这些零件串成闭环（图 9-1，L13）。

## 概念清单
- **持续学习 vs 持续进化**（continual learning / 持续进化）｜旧意义的持续学习是“学新忘旧”，本章难点是无人标注当天对错｜权重层面叫持续学习，模型外围的自主系统叫持续进化｜用于区分“改模型”与“改系统”｜§开篇 L3、L11
- **保存经历 ≠ 从经历中学习**｜避免把日志/向量库当成学习｜学习=评价、对照、归纳、验证｜入库前必须经跨案例对照｜§开篇 L7
- **三层轨迹验证**（结果/过程/质量验证器）｜单靠模型自述不可靠｜依次问：办成没、以允许方式办成没、用户舒服没｜结果层读环境，过程层读政策库+动作轨迹，质量层用 Rubric 的 LLM Judge｜L23–45
- **学习信号四要素**｜总分指不出改哪｜成败等级、分维度结论、证据位置、失败类型标签，允许拒评｜低置信案例不进学习集｜L47
- **四种更新载体**｜能力的表示性质不同｜知识/Prompt+Skill/程序+Harness/参数｜按能表达到哪一层选载体，可组合｜表 9-2 L58–73
- **三层经验数据**｜原始轨迹不能当知识｜不可变轨迹/单次分析/跨轨迹归纳文档｜文档写适用场景、推荐与禁止做法、例外、证据来源、最近验证时间｜L79
- **系统提示学习**（System Prompt Learning）｜让模型用一句话提醒未来的自己｜带来源的最小 diff｜须同过边界集与保留集｜L101–103
- **边界集 / 保留集**｜只测失败案例会改坏旧能力｜触发失败的案例集 vs 正常工作的案例集｜前者须改善，后者不能退化｜L103
- **Skill / 系统 Prompt / Harness 分工**｜作用域不同｜Prompt 全局，Skill 按需加载，Harness 管权限与硬约束｜语境判断给 Skill，高风险否决给 Harness｜L99、L149
- **浏览器工作流（程序化经验）**｜重复任务不该每次重新探索｜带参数、前后状态检查、版本信息的小程序｜六步生命周期，失效回退完整 Agent｜L173–184
- **动作前/后验证 + 独立回放验证**｜防“每个按钮都点了但字段为空”｜执行前检查、执行后检查、最终状态检查，沙盒重置后完整回放｜全部通过才发布｜L180、L184
- **可证伪变更契约**｜“补丁小”不足以归因｜记失败证据、根因、组件、提案、预期修复、可能受损及对应用例｜执行前声明影响预测，下一轮验证｜L199
- **可撤销效果 / 反应式协效果**（Cordis）｜自改需要可撤销副作用与可发现依赖｜时间可组合性管“改了什么”，空间可组合性管“依赖什么”｜让一切（含 Agent 主循环）成插件｜L230–238
- **更新方法的更新**｜产物内容之外还能优化“产生产物的方法”｜五层搜索尺度，不是五种载体｜默认最内层，需要时向外｜L258
- **发现树 / 回放模拟器**（Dream-RSI）｜外层搜索每个候选都重跑 Agent 太贵｜把历史探索存成树，只揭示已展开子树｜在线/离线同接口，比较探索策略；只在历史内有保证｜L266–276
- **双循环**｜在线直接改正式 Agent 不安全｜在线只执行记证据，离线聚合、诊断、提案、过门槛发布｜靠版本化经验库和评估集连接｜L288
- **Voyager 三机制**｜单缺一项都会出问题｜自动课程+技能库+迭代提示（环境验证）｜缺课程不知学什么，缺验证库里积累错误，缺持久化每次从头｜L292–294
- **Harness 更新能力 vs 受益能力**｜端到端分数分不清谁的问题｜产生修改 vs 找到、激活、正确使用修改｜用表 9-3 四指标分层评估｜L300–309
- **三道安全边界**｜自进化可把一次错误变长期风险｜证据与指令隔离/待验证与正式隔离/安全机制不可自我修改｜见节点 20｜L344–350
- **睡眠学习**｜采集与整理分开，防偶发成功、故障、恶意输入立刻改写长期能力｜五步周期｜空闲或门控触发，局部补丁优先｜L354–362

## 递进能力
- 读完本章，Agent 比上一章多了：
  1. 给轨迹打带证据的结构化评价（三层验证、四要素信号、可拒评）
  2. 把一类失败路由到合适载体（知识/指令/程序/参数）
  3. 从多条失败轨迹归纳出最小规则，并经边界集+保留集验证
  4. 把重复操作编译成带检查的程序，并在失效时回退探索
  5. 以隔离分支+变更契约自我修改代码，经门槛发布
  6. 把学习闭环拆成在线执行与离线进化，并长期整理、淘汰、回滚
- 依赖前面章：第二章（上下文学习、压缩、Skill、KV Cache、上下文腐化）；第三章（知识抽取/聚类/检索、User as Code 两阶段）；第五章（Coding Agent、工具创造）；第七章（评估、LLM-as-a-Judge、τ²-bench telecom）；第八章（SFT/蒸馏/RL）；第一章（最小 diff + 可回滚、三层护栏、框架对比表、发现循环）。
- 伏笔：本章承担第一章发现循环的“实验与反馈”环节（L409）；SFT/RL 数据来源于稳定的对话轨迹（L149、L254）。第九章是最后一章，之后只有思考题（L417–425）。

## 关卡候选
| 任务 | 事故（玩家看得见的失败） | 被逼出来的零件 | 对应因果链节点 |
|---|---|---|---|
| 客服轨迹分诊 | 只有总分时，“结果对但违规承诺”“结果错但语气好”得分相同，玩家无法判断该修什么 | 三层验证器 + 带证据/类型标签/可拒评的诊断输出 | 3、4 |
| 把话说给了工具 | 需要号码时，Agent 把“请您提供电话号码”作参数连调五次、全报错、最后转人工 | 从失败轨迹提炼的最小规则（先向用户要，再查）+ 边界集/保留集回归 | 7、8 |
| 规则把失败写进规范 | 模型归纳出“连续三次失败即转人工”，而本环境转人工必判失败，通过率反降 | 独立于提炼者的验证器、发布前回归门 | 8 |

## 容易讲错的地方
- 保存经历不等于学习；向量库/长上下文只能找回案例，不做跨案例对照（L7）。
- 本章的“持续学习”不是早年“学新忘旧”问题，遗忘只是子问题（L3）。
- 用户满意不等于合规；总分不能当学习信号；低置信结论宁可排除也不固化（L9、L47）。
- 反思本身不是证据，须有环境结果、跨轨迹支持、新任务正向迁移（L89）。
- 模型会把观察到的高频行为当作应然（L113）；提炼材料决定归纳深度（L111）。
- 系统提示学习不是让模型重写整份 Prompt，而是带来源的最小 diff，且与第二章“怎么写好 Prompt”不是一回事（L103）。
- Skill 管语境判断，Harness 管硬否决，二者不能互相替代（L149、L197）。
- 动作成功≠任务成功；定位信息（XPath/CSS）不能证明任务完成（L177–179）。
- 载体由“能力的表示性质”决定，而非“是否长期稳定”（L252）。
- 优化“更新方法”的五层是搜索尺度，不是五种新载体；历史回放也不是第五种载体，而是产生并验证提案的新机制（L258、L276）。
- 回放不是世界模型，不保证旧树得分高的策略能迁移（L274、L272）。
- 评价不能只看端到端分数，须区分更新能力与受益能力（L300）。
- LLM 摘要不是净化；模型自报置信度不能当批准门槛（L346）。
- 自我进化上限取决于承载系统的可组合性，而非模型代码能力；模型写的插件不能自动升级为正式插件（L238–240）。
- 睡眠学习是认知类比，不要求真在夜间；Claude Code 当前公开机制不能简单等同夜间后台任务（L354、L364）。
- 只解决当前失败案例却在其他案例退化，不算成功进化（L319）。
