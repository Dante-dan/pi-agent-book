# 第 01 站　缸中之脑长出手

> 这是[π 工坊](https://pi.duanjl.com/)第 01 站的手册。**先去玩，卡住了或者想知道得更深，再回来翻。** 游戏里带下划线的词，点一下会直接跳到这里对应的小节。
>
> 配套任务：[▶ 1-1 第一单](https://pi.duanjl.com/#/play/1-1) · [▶ 1-2 白纸黑字](https://pi.duanjl.com/#/play/1-2)

1981 年，哲学家普特南提出过一个思想实验：把一颗大脑泡在营养液里，用电线接上一台计算机，给它喂足够逼真的信号。这颗大脑会觉得自己正在散步、吃饭、读书，而它其实哪儿也没去。这就是“缸中之脑”。

大模型的处境和它很像，只差一点：**连那台喂信号的计算机都没有**。它读过互联网上数不清的文字，能写诗、能讲解量子力学，但此时此刻你桌上那份 `orders.json` 里写了什么，它一个字也看不到。

这一站你是空间站的总设计师。站上只有一颗这样的主脑。你要做的，是在一次次事故里弄明白它还缺什么，然后给它装上。走完两个任务，你会亲手拼出全书那个公式：

> **Agent = LLM + 上下文 + 工具**

## 这一站你会被逼出来的四个零件

| 事故 | 你会查出什么 | 被逼出来的零件 | 对应的概念 |
| --- | --- | --- | --- |
| 它在胡说 | 上下文舱里根本没有文件内容 | read 工具 | [工具](#c-tool) |
| 一片寂静 | 结果回舱了，但没人再呼叫主脑 | 循环 | [Agent 循环](#c-loop) |
| 有心无力 | 它算对了，却没东西可以写文件 | write 工具 | [动作](#c-action) |
| 它说完成了 | 没人核对，它说完成就算完成 | 验收信标 | [验收与闭环](#c-verify) |

下面每一节讲一个概念，都按同一个顺序：**为什么会有它 → 它是什么 → 怎么用**。

<a id="c-llm"></a>

## 主脑：只会接话的大模型

### 为什么先讲它

因为后面所有零件，都是为了弥补它的短处才存在的。不知道它短在哪儿，就不知道那些零件在补什么。

### 它是什么

大模型干的事情，说到底只有一件：**读完给它的全部文字，接出下一段最像样的文字。**

任务 1-1 里，你什么零件都没装就发射了。主脑答得有零有整：

> 已支付订单合计 128.50 元，共 23 笔，客单价约 5.59 元。

可账本上一共只有 8 笔订单。它没有撒谎，撒谎得先知道真相。问它“一共收了多少钱”，最像样的下一段文字就是一个金额，于是它给了一个金额。

战国时的赵括熟读兵书，谈起用兵来连他父亲都驳不倒。等到真领兵去了长平，四十万人没能回来。读过所有兵书和看得见眼前的战场，是两回事。

| 没有工具时，模型可能的两种表现 | 说明 |
| --- | --- |
| 编一个像样的答案 | 提线木偶演的就是这种。危险之处在于它看起来完全正常 |
| 老实说“我看不到文件” | 现在的真模型多半会这样。诚实，但活还是没干成 |

两种表现的病根是同一个：它没有眼睛，也没有手。

### 怎么用

把模型当成一个极其博学、但被关在屋里的顾问。它能想，不能看，不能动。**想让它干活，先想清楚怎么把外面的东西递给它。**

<a id="c-context"></a>

## 上下文舱：模型此刻知道的全部

### 为什么会有它

事故调查里的第一条线索，是让你去点开上下文舱里的每一块。你会发现里面只有两块：一块系统提示，一块你的提问。“数据在 orders.json 里”对主脑来说是几个汉字加一个文件名，不是一个可以打开的东西。

### 它是什么

**上下文（context）是模型这一次被调用时，能看到的全部文字。** 游戏里它是那根横放的玻璃舱，里面的每一块是一条消息。

| 方块颜色 | 是什么 | 谁放进去的 |
| --- | --- | --- |
| 紫 | 系统提示 + 工具说明书 | 空间站的设计者，也就是你 |
| 橙 | 提问 | 地面 |
| 青 | 主脑自己说过的话 | 主脑 |
| 绿 | 工具返回的结果 | 空间站 |
| 红 | 工具返回的报错 | 空间站 |

模型知道的东西只有两个来源：训练时读过的，和此刻上下文舱里装着的。除此之外的一切，它要么不知道，要么在猜。

### 怎么用

遇到 Agent 表现不对，第一件事不是换模型，而是**去看它到底收到了什么**。绝大多数“模型变笨了”，其实是该给的东西没给到。

<a id="c-memory"></a>

### 它不记得上一次

任务 1-1 装上循环之后，留意第 2 次呼叫：扫描环又从舱头扫到了舱尾。喂给主脑的不是“刚读到的文件内容”，而是**舱里的全部，从第一块开始**。

因为模型不记得第 1 次呼叫时发生过什么。每一次呼叫对它来说都是第一次。

电影《记忆碎片》的主角莱纳德记不住十几分钟之前的任何事。他的办法是把重要线索拍成拍立得、写成纸条，最要紧的直接纹在身上。每次“醒来”，他都先把这些东西从头看一遍，才知道自己是谁、正要干什么。

**上下文舱就是模型的纹身和拍立得。** 这件事有两个后果，后面的站点会反复用到：

- 舱里没有的，模型就不知道。所以“往舱里放什么”是一门正经学问，第 02 站专门讲。
- 舱里有的，每次呼叫都要重新读一遍。读得越多，越慢、越贵。

<a id="c-tool"></a>

## 工具：让它开口要东西

### 为什么会有它

第一次事故的结论是：上下文舱里没有文件内容。那就得想办法把文件内容弄进去。你可以每次手动贴进去，可那样的话，要这座空间站何用。

### 它是什么

办法出奇地朴素，分三步：

1. 在上下文舱最前面放一份**说明书**，告诉模型：有个叫 `read` 的东西，给它一个路径，它会把文件内容还给你。
2. 模型想读文件时不直接回答，而是输出一段格式固定的文字，意思是“请帮我执行 read，路径是 orders.json”。这叫**工具调用**。
3. 空间站认出这段文字，替它真的去读，再把读到的内容放回上下文舱。

模型从头到尾没碰过文件。它像餐厅里的客人：看菜单，点菜，等菜上桌。后厨在哪儿、灶台长什么样，它不知道也不需要知道。

在游戏里点一下 read 舱，能看到模型拿到的那份说明书原文。它只有三样东西：

| 组成 | read 的实际内容 | 作用 |
| --- | --- | --- |
| 名字 | `read` | 模型点菜时报的菜名 |
| 描述 | 读文件内容；文本最多返回 2000 行或 50KB；大文件用 offset 接着读 | 告诉模型什么时候用、有什么限制 |
| 参数格式 | `path` 必填，`offset`、`limit` 选填 | 告诉模型工单该怎么填 |

### 怎么用

记住一句话：**工具调用是请求，不是动作。** 模型说“请帮我读”，这句话本身什么也不会改变。决定这个请求会不会被执行、怎么执行的，是你设计的那部分程序。

<a id="c-harness"></a>

## Harness：你设计的这座空间站

模型之外、把一切接起来的那部分程序，叫 **Harness**，原意是马具。马再有劲，没有马具也拉不了车。

你在游戏里扮演的就是 Harness 的设计师。往上下文舱里放什么、给模型哪些工具、工具请求来了执不执行、结果回来之后要不要再呼叫主脑、什么时候算做完，这些都不是模型的事，是 Harness 的事。

本站背后跑的 Harness 是 [Pi](https://github.com/earendil-works/pi)。它把这些职责分在了几个包里：

| 包 | 负责什么 |
| --- | --- |
| `pi-ai` | 和各家模型服务说话，把不同厂商的格式统一起来 |
| `pi-agent-core` | 循环本身：维护消息、调度工具 |
| `pi-coding-agent` | 把循环、文件工具、会话和界面装配成一个能用的助手 |

<a id="c-loop"></a>

## Agent 循环：再来一次

### 为什么会有它

装上 read 之后你再次发射，文件内容确实被读回了上下文舱，然后整座空间站一片寂静。地面指挥说：“我等了半天，你的站一个字都没回。”

数一数主脑被呼叫了几次：一次。那一次它说的是“请帮我读文件”，说完这次呼叫就结束了。结果回来的时候，没有人再去叫它。

### 它是什么

**循环就是那个“再来一次”。** 工具结果回舱之后，再呼叫一次主脑，把舱里的一切重新给它看；它如果又要工具，就再执行、再呼叫，直到它不再要工具为止。

用伪代码写出来只有十来行。它不是 Pi 的真实接口，但骨架是一样的：

```js
messages = [系统提示, 用户提问]

while (true) {
  reply = await 调用模型(messages, 工具说明书)  // 每次都把全部 messages 发过去
  messages.push(reply)

  if (reply 里没有工具调用) break              // 模型不再点菜，循环结束

  for (call of reply.工具调用) {
    result = await 执行工具(call)               // 点菜的是模型，做菜的是 Harness
    messages.push(result)
  }
}
```

游戏里那圈环绕空间站的发光轨道，就是这个 `while`。全书后面讲的所有东西，上下文工程、记忆、评估、多 Agent，都是在这十来行的某个位置上做文章。

### 循环什么时候停

停下的条件只有一个：**模型的输出里没有工具调用。** 也就是说，停不停由模型说了算。它要是一直点菜，循环就一直转。

希腊神话里西西弗斯推石头上山，石头滚下来，再推，永无止境。一个验收永远过不了的 Agent 就是这副样子，而且每推一次都在烧钱。所以任何认真的 Harness 都会在循环外面再加保险。这座工坊加了两道：一次发射最多 12 个回合，最多 120 秒。

### 怎么用

看到“Agent”这个词，脑子里就该浮现这个循环。别人说的“Agent 框架”“Agent 平台”，剥到最里面都是它。

<a id="c-action"></a>

## 动作：从看见世界到改变世界

### 为什么会有它

任务 1-2 要的不是一句话，是一份文件。主脑读了说明、读了订单、算出了正确的数，然后说：“我没有能写文件的工具。”任务失败。

### 它是什么

工具大致分两类：

| 类别 | 例子 | 效果 |
| --- | --- | --- |
| 感知 | `read`、`ls` | 把外面的信息带进上下文舱 |
| 动作 | `write`、`edit` | 改变外面的世界 |

只有感知工具的 Agent，充其量是个解说员。

### 怎么用

**你给它什么工具，就等于划定了它能做到什么。** 这句话反过来读同样要紧：你不想让它做的事，最可靠的办法是根本不给它那个工具。这座工坊没有给主脑任何能执行命令的工具，原因就在这里。

<a id="c-verify"></a>

## 验收与闭环：别听它怎么说

### 为什么会有它

装上 write 之后，主脑写了一份报告，然后说“日结完成 ✅”。地面指挥拿账本一核对：报告是错的，它把退款和未付款的订单也算了进去。

它没有撒谎。它确实写了报告，也确实不知道报告是错的。问题是：在你的空间站里，没有任何东西核对过。

### 它是什么

1987 年里根和戈尔巴乔夫签《中导条约》时，里根引了一句俄国谚语，后来成了名言：

> Доверяй, но проверяй。信任，但要核实。

验收信标就是那个“核实”。它是一段普通的程序，拿报告和账本逐项比对。它不懂语言，不会被说服，也不看模型的语气。

更要紧的是它被做成了一个**工具**，装进了循环里。再发射一次，看这六步：

1. 读 `README.md` 和 `orders.json`。两张工单是一起递出来的，因为这两件事互不相干。
2. 写 `report.json`：8 笔，4450 分。
3. 调用验收。**信标红了。**
4. 读到不通过的原因，重写：5 笔，3100 分。
5. 再次验收。**信标绿了。**
6. 不再要工具，交付。

红灯的原因没有弹窗，没有中断程序，它只是作为一块普通的工具结果**落回了上下文舱**。下一次呼叫时主脑读到它，于是知道自己错在哪儿。这就是“闭环”：**动作的结果，回到做决定的地方。**

| | 没有验收的循环 | 有验收的循环 |
| --- | --- | --- |
| 谁说“做完了” | 模型自己 | 一段不会被说服的程序 |
| 做错了会怎样 | 你事后才发现 | 原因回舱，模型当场重做 |
| 你需要信任什么 | 模型的每一句话 | 验收程序写得对 |

右边这一列并非万无一失。验收程序本身可能写错，也可能只查了一部分。怎样的验收才算数，是第 07 站的主题。

### 怎么用

**别问模型“做完了吗”，给它一个能自己去按的验收按钮。** 写代码的 Agent 让它能跑测试，做报表的 Agent 让它能对账。验收报出的原因写得越具体，循环转的圈数越少。

## 这座工坊哪里是真的，哪里是假的

演示系统最怕不说清楚自己演了什么。这里列个明白账。

| 东西 | 真假 | 说明 |
| --- | --- | --- |
| Agent 循环 | **真** | 服务器上跑的是 Pi 1.5.2 的运行时，事件是它发出来的 |
| `read` / `write` | **真** | 是 Pi 自带的工具，说明书一字未改 |
| 验收信标 | 自制 | 为这一站写的验收工具，源码公开 |
| “没装循环” | **真** | 工具结果回舱后，服务端确实不再调用模型 |
| 文件系统 | **假** | 工具读写的是一份只存在于内存里的虚拟文件，每次发射各用各的 |
| 提线木偶 | **假** | 没有 key 时使用的、照着剧本输出的模型 |
| token 数 | 估算 | 按字符粗算，只用来决定方块的大小 |

把模型换成木偶，循环却照转不误，这件事本身就值得琢磨：**循环并不关心主脑里装的是什么**。它只认一种约定，输出里有没有工具调用。

## 带走三句话

1. 模型只知道训练时读过的，和此刻上下文舱里装着的。
2. 工具调用是请求，不是动作。执行的是 Harness，记住这件事的是上下文舱。
3. 想让 Agent 靠谱，就把验收装进循环，让结果回到做决定的地方。

## 想一想

<details>
<summary>1. 任务 1-1 里，如果空间站执行完 read 却忘了把结果放回上下文舱，下一次呼叫时主脑会怎样？</summary>

它会看到自己发出过一个 `read` 请求，却看不到结果。对它来说，这次读取等于没发生。它可能再请求一次，也可能直接开始猜。舱里没有的，模型就不知道。

</details>

<details>
<summary>2. 任务 1-2 里，主脑一口气递出了两张 read 工单。这样做有什么前提？</summary>

两件事互不依赖：读 `README.md` 不需要先知道 `orders.json` 的内容。如果第二步要用第一步的结果，就只能分两个回合。

</details>

<details>
<summary>3. 把验收的不通过原因从“paidCount 与账本不符”改成只说“不通过”，会发生什么？</summary>

模型知道错了，但不知道错在哪儿，只能瞎改再试，回合数会变多，也可能撞上 12 回合的上限。报错写得好不好，直接决定循环转几圈。

</details>
